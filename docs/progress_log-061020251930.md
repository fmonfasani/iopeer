+# 📊 Finrome diario — módulo de reportes IOpeer
+**Fecha:** Lunes 06/10/2025 — **Zona horaria:** GMT-3 (Argentina)
+
+---
+
+## 🧭 Resumen ejecutivo
+- Se orquestó un **módulo de reportes** completo en NestJS que levanta métricas de runs, workflows y schedules directamente desde Prisma y produce salidas en texto y HTML listas para distribuir.
+- El reporte ahora se puede **embelezar automáticamente** gracias a una cadena de beautifiers con fallback (Ollama → HuggingFace → Groq) controlada por `BEAUTIFIER_PROVIDER`.
+- Se automatizó el **envío recurrente** vía cron a Slack y correo electrónico, con endpoints manuales para disparar reportes ad hoc.
+
+---
+
+## ⚙️ Backend — ReportService
+- `ReportService.buildStatusReport()` agrega totales por estado (`PENDING`, `RUNNING`, `SUCCESS`, `ERROR`, `CANCELLED`) y calcula el total de runs, workflows activos y schedules activos utilizando Prisma en paralelo para minimizar latencia.【F:apps/api/src/reports/report.service.ts†L1-L39】
+- Incluye ranking de los **5 workflows más ejecutados** y un feed de los **10 runs más recientes** con duración y errores truncados para monitoreo rápido.【F:apps/api/src/reports/report.service.ts†L40-L85】
+- Devuelve tanto `text` (Markdown/Slack) como `html` (para email) junto con metadatos que permiten enriquecer dashboards o integraciones posteriores.【F:apps/api/src/reports/report.service.ts†L86-L120】
+

+## 🤖 Beautifier omnicanal
+- `BeautifierStrategy` arma dinámicamente la cadena de proveedores priorizando el configurado en `BEAUTIFIER_PROVIDER` y hace fallback registrando logs cuando un proveedor falla.【F:apps/api/src/reports/beautifier/beautifier.strategy.ts†L1-L42】
+- **Ollama** usa el endpoint local `OLLAMA_URL` y modelo `OLLAMA_MODEL`, ejecutando un prompt ejecutivo para transformar el Markdown.【F:apps/api/src/reports/beautifier/beautifier.ollama.service.ts†L1-L31】
+- **Hugging Face Inference** consume `HF_API_URL` + `HF_API_TOKEN`, parametrizado con `max_new_tokens` y `temperature` bajas para resúmenes consistentes.【F:apps/api/src/reports/beautifier/beautifier.hf.service.ts†L1-L34】
+- **Groq** utiliza `GROQ_API_KEY` y `GROQ_MODEL`, retornando respuestas concisas; si algún proveedor falla, el original se devuelve intacto.【F:apps/api/src/reports/beautifier/beautifier.groq.service.ts†L1-L23】【F:apps/api/src/reports/beautifier/beautifier.strategy.ts†L33-L42】

+## 🔔 Notificaciones y scheduling
+- `ReportScheduler` ejecuta un cron configurable (`REPORT_CRON`, default mediodía) y manda el informe a Slack y email en paralelo usando `Promise.allSettled`, logueando cualquier error sin frenar el flujo.【F:apps/api/src/reports/report.scheduler.ts†L1-L35】
+- También expone `runNow()` para ejecuciones manuales, reutilizando la misma ruta de Slack/Email para consistencia.【F:apps/api/src/reports/report.scheduler.ts†L37-L45】
+- `SlackNotifier` verifica `SLACK_WEBHOOK_URL` y publica payloads JSON simples; si no hay webhook, registra una advertencia y continúa.【F:apps/api/src/reports/slack-notifier.ts†L1-L21】
+- `EmailNotifier` monta un transporte SMTP solo si `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` y `REPORT_EMAIL_TO` están configurados, usando `REPORT_EMAIL_FROM` como remitente predeterminado.【F:apps/api/src/reports/email-notifier.ts†L1-L39】

+## 🕹️ Exposición vía API
+- `ReportController` publica `POST /reports/beautify`, que construye el informe, lo pasa por la cadena de beautifiers y luego lo envía a Slack, devolviendo un `ok` para integraciones de consola o CI.【F:apps/api/src/reports/report.controller.ts†L1-L20】
+- El módulo declara dependencias en `ReportModule`, exportando tanto `ReportService` como `BeautifierStrategy` para que otros bounded contexts puedan reutilizar la misma lógica si necesitan automatizar reportes temáticos.【F:apps/api/src/reports/report.module.ts†L1-L31】
